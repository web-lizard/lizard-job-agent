# Архитектура

## Общая схема

Lizard Job Agent состоит из четырёх частей:

1. `background.js` хранит настройки, читает локальное резюме, вызывает DeepSeek и управляет постоянным окном.
2. `content.js` работает в контексте страницы: определяет её тип, ищет поля и вставляет значения.
3. `popup.*` показывает состояние активной вкладки и отправляет команды фоновому и content-скриптам.
4. `options.*` управляет ключом API, поведением заполнения и настройками поиска.

Обмен выполняется через сообщения `browser.runtime`. Типы сообщений и модульные заготовки находятся в `src/shared/messages.ts`.

```text
Панель ──► background.js ──► DeepSeek API
   │              │
   │              └──► browser.storage.local / resume.json
   │
   └──► content.js ──► страница HH.ru или Google Forms
```

## Поток заполнения

1. Панель запрашивает описание текущей страницы.
2. Content-скрипт сканирует доступные документы и возвращает найденные поля.
3. Подтверждённые данные сопоставляются локально с `resume.json`.
4. Для открытых вопросов background-скрипт формирует обезличенный контекст и вызывает DeepSeek.
5. Content-скрипт вставляет черновики и генерирует события `input`/`change`.
6. Пользователь проверяет данные и вручную отправляет форму.

## Источники данных

- `resume.json` — локальный источник подтверждённых фактов; исключён из Git.
- `browser.storage.local` — настройки интерфейса и API.
- DOM текущей страницы — вопросы, описание вакансии и уже введённые значения.
- DeepSeek API — только генерация текста для открытых вопросов.

## Правила безопасности

- content-скрипт не получает API-ключ;
- ключ не выводится в журнал и диагностику;
- контактные данные удаляются перед отправкой резюме модели;
- заполненные поля не перезаписываются без явной настройки;
- код не вызывает `submit()` и не нажимает кнопки отправки;
- резервные копии и персональные файлы не входят в сборку.

## Два слоя исходного кода

Корневые JavaScript-файлы — стабильная реализация версии 0.10, которую загружает `manifest.json`. Каталог `src/` содержит типизированные доменные модули и Vue-компоненты, которые проверяются TypeScript и модульными тестами. При переносе функции в `src/` поведение корневой версии должно сохраняться интеграционными тестами.

Такое разделение временное. Не следует добавлять новую параллельную копию с номером итерации: изменяйте стабильные точки входа и покрывайте поведение тестом.
